# Ruby / Rails の規約

言語のデフォルトや一般的な慣習と**異なる**点だけを挙げる。ここに書かれていないことは既存コードの書き方に合わせる。

## 省略記法（Ruby 3.1以降）

ハッシュリテラルとキーワード引数は、省略できる場合は省略する。

- キーワード引数: `foo(param:)` は `foo(param: param)` と同じ
- ハッシュ値: `{ name: }` は `{ name: name }` と同じ

## Serializer

単純な属性はブロックではなく `attributes` メソッドを使う。

```ruby
attributes :id, :name
```

## サービスクラスを作らない

原則として新規に `app/services` のサービスクラスを作らない。既存のモデル内で private メソッドによる責務分離を優先する。

## エラー処理

- 事前バリデーション + 早期returnパターンを使う
- 例外を投げる前に、バリデーションで弾けるものは弾く
- サイレントな失敗（`return {}` など）を避け、明示的なエラー通知か早期returnにする

## 重複の共通化

- 同じパターンの処理（通知、API呼び出しなど）は共通メソッドに抽出する
- 共通パラメータを持つメソッドは基底メソッドを作って委譲する

## メソッド名

役割が名詞だけで表現できるなら動詞を省く（`generate_notice_message` → `notice_message`）。意図が明確なら短い名前を優先する。
